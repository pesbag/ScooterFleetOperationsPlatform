# ניקוי קוד ללא שינוי התנהגות

## מה צומצם

- הוסרו `StationApi/StoreDatabaseSettings/StationsDatabaseSettings.cs` ו־`StationApi/Dtos/StationStatusDto.cs`: לא נמצאו צרכנים, רישומי DI או מיפויים המשתמשים בהם.
- הוסרה `HasChangedFrom` מה־DTO של המעבד: לא היו קריאות אליה.
- הוסרו שלושה משתני topic לא בשימוש בנקודת הכניסה לקליטה ושדה bootstrap לא בשימוש ביצרן Kafka. הגדרות ה־topics שה־worker קורא נשמרו.
- שליחת Kafka בשלושת שירותי הקליטה אוחדה ל־`SendBatchAsync` ביצרן הקיים. נשמרו בחירת המפתח, JSON, שליחה מקבילית, המתנה לכל התוצאות, flush של עשר שניות והעברת שגיאות וביטול. הפענוח והוולידציה נשארו בכל שירות.
- הוסרו using מיותרים וקוד ישן בהערות. ב־SmartFleetEngine הוסרו בדיקות stale חוזרות אחרי המסלול שכבר מחזיר תוצאה עבור מידע ישן.
- הוסרו שש הפניות לחבילות מפרויקטי הייצור: SQL Server מה־API; Extensions.Hosting, EF Core, EF Design, Pomelo ו־Redis מהקליטה. חבילות ה־Hosting וה־HTTP הפעילות נשמרו. לבדיקות נוספה הפניה לאותה גרסת Confluent.Kafka שכבר קיימת במערכת, כדי לבדוק את קוד היצרן ללא broker.

הספירה היא של קובצי C# שבבקרת גרסאות ושל הקובץ החדש בבדיקות, ללא bin/obj; שורות כוללות רווחים והערות. קובצי Views, CSS ותיעוד אינם נכללים. המיגרציות נכללות ונשארו ללא שינוי.

## אימות

- הבנייה והבדיקות המקומיות עברו לפני השינוי.
- לאחר הסרת החבילות בוצע `dotnet restore BikeFleet.sln`.
- `dotnet build BikeFleet.sln --no-restore`: אפס שגיאות ואפס אזהרות.
- `dotnet run --project FleetTests --no-build`: בדיקות לוגיקה, JSON, validation, hashing, מטמון, HTTP ורינדור Razor. נבדקים גם הרשאות, נגישות הרשמה והתנתקות ומעבר סטטוס משימה מול fixture.
- שבע בדיקות Kafka ממוקדות משתמשות ב־IProducer מדומה: המתנה לשליחות לפני flush, topic/key/token, התאמת JSON כולל null ואפס, flush מוצלח, כשל, ביטול ואצווה ריקה.
- `git diff --check`: תקין.

לא שונו Controllers, Views, CSS, נתיבי API, סכמות אחסון, חוזי JSON, הגדרות זמן או מיגרציות. לא הורצו Docker, Kafka אמיתי או מחזור הרשמה/כניסה/יציאה מול מסד אמיתי. הצלחת הבדיקות המקומיות אינה טענה לאימות מקצה לקצה.
