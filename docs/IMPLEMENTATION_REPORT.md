# דוח מסירה — Bike Fleet

## A. השינויים

המערכת חזרה לתחום האופניים ולשם Bike Fleet. נשמרו C#, ASP.NET Core, Razor Views, MySQL, MongoDB, Kafka ו־Redis, ללא JavaScript או תשתית חדשה. מקור הייצור הוא Citi Bike באמצעות GBFS; מחולל נתוני ההדגמה הוסר. שופרו אמינות המידע, מטמון, סגירת תקלות, שמות תחנות, זמני תחזית והרשמת רוכבים.

המקור החי נבדק בקריאת HTTP אמיתית עם ה־DTO והניתוח של הפרויקט: 2,519 תחנות, 2,452 עם מידע עדכני, 1,287 Healthy ו־420 Critical. אלה נתוני רגע הבדיקה, ללא היסטוריה מקומית, והם משתנים. התחנות הנותרות כוללות מצבים נוספים; אין הבטחה שכל התחנות יהיו תקינות.

## C. זרימת הנתונים

GBFS נמשך אחת ל־60 שניות עבור זמינות ופעם בשעה עבור פרטי תחנות, לפי ההגדרות. לכל לולאה בקשה עוקבת; אין חפיפה בין מחזוריה. הודעות נשלחות ל־Kafka. המעבד שומר פרטי תחנות ב־MySQL וסטטוס והיסטוריה ב־MongoDB, ואז משנה את גרסת המטמון. ה־API קורא דרך Redis במבנה cache-aside: פגיעה במטמון מחזירה נתונים קיימים ומחשבת מחדש את גיל המדידה; החטאה קוראת ממסדי הנתונים ושומרת ל־60 שניות בדיוק. כשל Redis מאפשר קריאה מהמסדים. תוצאות ריקות ושגיאות מסד אינן נשמרות כנתונים מוצלחים.

Razor מציג את התוצאה. דפי המעקב מקבלים meta refresh כל 60 שניות עם אפשרות השהיה; טפסי עריכה והרשמה אינם מתרעננים. זהו עדכון מחזורי, לא זרם מיידי: יש עיכוב מקור, קליטה, עיבוד ורענון דף. זמני דיווח הספק וקבלת המידע מוצגים בנפרד.

תחילית `citibike:` מבודדת את המקור החדש מנתונים קודמים. הרשומות הישנות נשמרות. נתון חסר אינו הופך לאפס, וקיבולת אינה מומצאת. הדשבורד מציג שש תחנות בסיכון גבוה, ולא מדגם מייצג של כל הרשת.

## D. תיקון סגירת תקלות

הקוד הקודם שמר את מצב הפעולה בלי מנגנון אחיד שחיבר בין התקלות שנותרו, המידע מהספק והנתונים שהוצגו לאחר השמירה. בנוסף, מצב הסיכון מהספק אינו מצב משימת העובד: סגירת משימה אינה משנה את מספר האופניים בפועל.

כעת נשמרים מצב הסגירה, זמן ומבצע במסד. לאחר שמירה מוצלחת נפסל המטמון והטופס מפנה מחדש לפרטי התחנה. מצב התפעול מחושב עם התקלות הפתוחות העדכניות; סגירת תקלה אחת אינה סוגרת אחרות. השלמת משימה יכולה ליישב התראות אוטומטיות מוכרות רק אם נתוני המקור כבר תקינים ועדכניים. תחנה עם מחסור אמיתי נשארת Attention; מידע ישן אינו הופך ל־Active. שגיאת API בשמירה מוצגת כשגיאה ולא כהצלחה.

נבדקו כללי המצב, הפסילה והפניית המסך. שמירת עסקאות מול MySQL אמיתי והשתקפותן דרך כל התשתית עדיין דורשות את בדיקת Docker אצלך.

## E. אימות והרשמה

כניסה בודקת משתמש פעיל וסיסמה מול ASP.NET PasswordHasher ומנפיקה cookie עם זהות ותפקיד. יציאה מבטלת את ה־cookie. ההרשמה שומרת משתמש במסד עם סיסמה מגובבת ותפקיד RIDER שנקבע בשרת; לקוח אינו יכול לבקש ADMIN. אימות שם, דוא״ל ואורך סיסמה מתבצע בשרת ומוצג בטופס. API תפעולי מוגבל ל־ADMIN/OPERATOR; ניהול משתמשים למנהל. כתיבות מוגנות ב־CSRF. רוכבים מקבלים מועדפים ודיווחים אישיים.

נבדקו hashing, validation, הרשאות ורינדור טפסים. מחזור הרשמה→שמירה→כניסה→יציאה מול מסד אמיתי אינו מסומן כנבדק.

## F. בדיקות ותוצאות

| פקודה / בדיקה | תוצאה בפועל |
| --- | --- |
| `dotnet build BikeFleet.sln --no-restore` | עבר: 0 שגיאות, 0 אזהרות |
| `dotnet run --project FleetTests --no-build` | עבר: 67 בדיקות עסקיות, בדיקות מטמון, HTTP ו־Razor |
| `dotnet run --project FleetTests --no-build -- --gbfs` | עבר: 69 בדיקות עסקיות, כולל מקור חיצוני אמיתי, וכל בדיקות המטמון/HTTP/Razor; exit code 0 |
| PowerShell `Parser.ParseFile` לכל `scripts/*.ps1` | תחביר תקין; לא הפעיל את הסקריפטים |
| חיפוש scooter, מקור Bird ו־DemoFleetWorker בקוד/תיעוד פעילים | לא נמצאו אזכורים; הוחרגו Git, תוצרי build ו־`.env` המכיל חשבון קיים |
| Docker Compose, קונטיינרים ו־smoke-test | לא הורצו, בהתאם לבקשתך לבצע בדיקות Docker בעצמך |

בדיקות Redis משתמשות בתחליף ממוקד: קריאה ראשונה, hit, TTL מדויק, JSON פגום, נפילה, פסילה מקומית, גרסת מעבד ופרטי תחנה. בדיקות HTTP משתמשות גם בתשובות מדומות לשגיאות וביטול. בדיקות Razor מריצות שרת HTTP אמיתי עם fixture ל־API, בודקות רינדור, CSRF, הרשאות, רענון, הפניה אחרי הצלחה ושגיאת שמירה מדומה. הן אינן בדיקות של מסד הנתונים.

בדיקה מוקדמת מצאה שאימות הרשמה דרך מאפייני record לא נבדק כראוי ברמת אובייקט. הבקשה הומרה למחלקה עם annotations על properties; ההרצה הסופית עברה לאחר התיקון.

## G. מגבלות ובדיקות שנותרו

- לא אומתו בהרצה זו Kafka, MySQL, MongoDB או Redis אמיתי; אין טענה לאימות מקצה לקצה.
- שינויי סכמת OperationsSchema הם תוספתיים, אך שדרוג מסד קיים בפועל דורש הפעלה אצלך. אין למחוק volumes.
- רינדור HTML נבדק; מעבר זמן אמיתי בדפדפן ובדיקה חזותית במובייל לא הורצו. CSS כולל התאמות רוחב ושבירת טקסט.
- מדדי השפעה ותחזיות זקוקים להצטברות קריאות ומשימות אמיתיות. שיפור לאחר פעולה אינו הוכחה לסיבתיות.
- אתר שכבר רץ מ־image ישן אינו מקבל את שינויי הקוד עד לבנייה והפעלה מחדש.
- חשבונות קיימים נשמרו, כולל כתובות דוא״ל ישנות אם ישנן; שינוי שם הפרויקט אינו משנה פרטי כניסה.

## H. הפעלה והשלמת אימות

פתח את `BikeFleet.code-workspace` ב־VS Code. בקובץ `.env` המקומי הוגדר מקור Citi Bike; ודא `APP_PORT=8080`. אם אין `.env`, הרץ פעם אחת `powershell -ExecutionPolicy Bypass -File scripts/setup.ps1`. מנהל seed נוצר רק במסד משתמשים ריק; פרטי seed אינם מאפסים חשבון קיים.

```powershell
# בדיקת תצורה בלבד; הפקודות כאן מיועדות להרצה אצלך
docker compose config --quiet
docker compose up -d --build
docker compose ps
powershell -ExecutionPolicy Bypass -File scripts/smoke-test.ps1
```

פתח http://127.0.0.1:8080 לאחר שהשירותים עלו. אפשר למחזור הקליטה הראשון להסתיים; בדוק זמן מדידה, דף Stations והבדלי מצבים. סקריפט smoke משתמש בפרטי המנהל מ־`.env`, יוצר רוכב בדיקה ושתי תקלות בדיקה, בודק הרשאות/סגירה/יציאה ומנקה אותן באמצעות סגירה והשבתת המשתמש. הוא אינו משלים משימת העברה אמיתית.
